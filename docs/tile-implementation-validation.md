# タイル分割読込 実装検証記録

## 2026-08-20 ローカル初回検証

ローカルの検証用マニフェストをスキーマ2へ切り替えた状態で起動したところ、初期画面の集計値が0件となった。ブラウザコンソールでは、タイルJSONを取得する処理がHTML応答をJSONとして解析しようとして失敗していることを確認した。次の検証では、生成済みタイルの公開パスとクライアント側の相対パス解決を確認し、正常なJSON応答を返すよう修正する。

URL解決をViteのベースパス基準に修正し、JSON以外を返す古いキャッシュは自動削除するようにした後、マニフェスト、サマリー、索引、および集約タイル2件がHTTP 200・`application/json`で返ることを確認した。集約タイルの内容も、それぞれ183件、2,887件の実データを含んでいた。

さらに、索引内の`tiles/...`はデータセット配下からの相対パスであることを確認した。クライアントがこの接頭辞を付けずにアプリ直下の`/tiles/...`を要求していたため、ViteのフォールバックHTMLを取得していた。データセット基準で相対パスを解決するよう修正し、集約タイルと詳細タイルの両方に同じ規則を適用した。

修正後、初期ズームおよびズーム11では7件の青い集約マーカーが地図に表示され、表示範囲の一覧更新では11,061件の座標付き店舗を詳細タイルから取得できた。これにより、低ズームの集約表示と詳細タイルの遅延読込が同じデータセットで動作することを確認した。

未読込の状態から「高槻市」を検索すると、検索索引を遅延取得して該当する詳細タイルを読み込み、348件の店舗を一覧表示できた。したがって、検索起点でも全店舗データを先に取得せず、該当タイルへ直接到達できる。

GitHub Pagesデプロイ後の公開版でも、スキーマ2のマニフェストを取得し、初期表示で7地域・11,061件の集約マーカーを表示できた。GitHub Actionsのタイル生成、静的配信、クライアント側の相対パス解決が本番のリポジトリ配下URLで連携していることを確認した。
