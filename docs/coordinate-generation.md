# 全店舗の事前座標化

## 方針

対象4地域のCOIN+店舗データは、公開時にブラウザから住所検索APIへ大量アクセスしない。代わりに、GitHub Actionsのビルド時にローカル住所辞書を用いて住所を緯度経度へ変換し、座標を店舗JSONへ含める。

国土地理院は地名検索APIを地理院地図からの利用を主に想定しており、長期提供を保証しないとしている。また、サービス運用を妨げる負荷に対してアクセスを遮断する場合がある。そのため、全店舗の一括座標化に外部の検索APIを繰り返し呼び出す方法は採用しない。[1][2]

変換には、東京大学CSISの住所マッチング技術をPythonへ移植した`jageocoder`と、全国街区レベル住所辞書を利用する。jageocoderのドキュメントは、大量の住所処理にはローカル住所データベースを利用する方法を案内している。[3][4]

## 実測結果

2026-08-20時点の公式COIN+ CSVから対象4地域の11,093店舗を生成し、10,966件の重複排除後住所を変換した。10,934住所が変換でき、店舗単位では11,061店舗に座標を付与できた。座標付き店舗の網羅率は**99.7115%**である。残る32住所は座標を持たず、地図ピン・範囲内一覧から除外するが、検索結果の一覧には残す。

| 項目               |   実測値 |
| ------------------ | -------: |
| 対象店舗数         |   11,093 |
| 重複排除後住所数   |   10,966 |
| 座標化できた住所数 |   10,934 |
| 座標付き店舗数     |   11,061 |
| 店舗単位の網羅率   | 99.7115% |

GitHub Pages公開版の初回生成では、取得時点の公式CSVから**11,062店舗**に座標を付与し、**31店舗**を地図外として扱った。公開版での座標付き店舗の網羅率は**99.7205%**であり、公式CSVの更新時刻によってローカル検証時の件数と1件程度変わる場合がある。

## 月次更新時の処理

月次ワークフローは、公式CSVの取得、ローカル辞書のキャッシュ復元、全住所の再変換、座標付きJSONとマニフェストの生成、GitHub Pages公開を順に実行する。住所辞書は街区レベルの代表点を返すため、番地・建物名の詳細が住所に含まれる場合でも、地図上の位置は街区代表点になる可能性がある。
